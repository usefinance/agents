0:00–1:00 (1 minute). Welcome. This is a presentation and demonstration for researchers. Scan the QR for these slides and the demo files, linked from the reference slides. Programming experience varies; we will focus on directing and checking work. Explain the 40 + 10 + 10 schedule.
01 · Start with a task

One task, two workflows

“Check this dataset and make a reproducible figure.”

Conversation led

You carry the work between turns

  • Ask for an approach or code.
  • Copy, run and inspect it.
  • Bring errors back to the conversation.
Agent led

The system works in the project

  • Give a goal and a workspace.
  • It inspects, edits, runs and checks.
  • You review the files and evidence.
Both need your research judgment. The amount of work delegated changes.
1:00–5:00 (4 minutes). Ask who has copied AI-generated code into Stata, R or Python. Walk through one error-and-retry cycle. These are two workflows, not a rigid classification of products. A chat application may support the second workflow too. Neither establishes scientific correctness.

8:00–10:00 (2 minutes). Correct the common misconception that browser chat cannot use files or run code. Chat is an interaction style; an agent can use that interface. A terminal does not imply a local model, and a browser does not determine where all tools execute.

10:00–12:00 (2 minutes). These are modes of working, not fixed product tiers. Demonstrate the distinction with a replication task. You can steer an agent while it works. A prompt asking it to plan is useful, but the enforcement of a product's plan mode depends on that product.

Definitions: Anthropic: model and harness · OpenAI: harness and environment

12:00–15:00 (3 minutes). Explain harness in ordinary terms: software around the model that supplies context, routes tool calls, manages the session, and applies controls. The model does not directly edit a file; a tool performs the edit. Model families are different from agent products. The same model can be deployed in different harnesses. This is a teaching diagram, not a claim that every implementation has identical components.
06 · What the harness provides

Four things to look for

Context

Relevant files, project instructions and earlier results.

Tools

Search, file editing, shell commands and connected services.

Environment

The files and software where commands actually run.

Control

Access boundaries, approvals and changes you can inspect.

Available in the project ≠ already read into the model’s context.
15:00–17:00 (2 minutes). Context has limits and may be summarized as work continues. A large context window does not mean every project file has been read or will be remembered verbatim. Point out that Stata, R or Python must actually be available in the execution environment; a model knowing syntax is not enough.

19:00–22:00 (3 minutes). This is a recommended research workflow, not a fixed algorithm every agent follows. Human judgment matters throughout, especially defining the question and reviewing evidence. Use a merge as the running example: count keys before and after, investigate duplicate rows, correct and rerun.
09 · A brief the agent can check

State the task and the evidence

Input Inspect this synthetic firm-year dataset. Report columns, missing values and duplicate firm-year keys.

Goal Plot the yearly median of firm-level ROA, calculated as 100 × net income / year-end total assets.

Constraints Use positive assets and non-missing inputs. Report exclusions. Keep the input file unchanged.

Completion Save the figure, summary table and run instructions. Run the script and show what you checked.

For a real study, you supply the justified variable definitions and sample rules.

22:00–25:00 (3 minutes). Read the four pieces of the brief. The requested ratio uses contemporaneous total assets as a simple teaching definition; many real research designs use other definitions. Do not let the agent silently choose winsorization, identification, filters or missing-value treatment. The demo has no regression or causal claim.
10 · Review what actually happened

Ask for evidence you can inspect

What changed?

Read the file diff and inspect the generated artifacts.

What ran?

Check the command, its output and the run instructions.

What was checked?

Look at counts, keys, units and a manual calculation.

What remains uncertain?

Read the assumptions, limitations and unfinished checks.

Code that runs can still answer the wrong research question.
25:00–27:00 (2 minutes). A fluent delivery message is not evidence that a check ran. Open the actual result. An explanation of code is helpful, but does not independently verify its correctness. Review the sample and meaning of variables, not only syntax or a green test result.

27:00–30:00 (3 minutes). Use examples relevant to finance researchers. Coding agents can help with identifier mapping, replication scripts and documentation, but a successful merge may still be economically wrong. Cross-language replication requires matching defaults, sample rules and estimation choices. Avoid promising fixed time savings.

13 · Common failure modes

Errors can look convincing

A merge duplicates rows

Check key uniqueness and row counts before and after.

A ratio uses the wrong denominator

Trace the definition and calculate one observation yourself.

A figure hides excluded years

Inspect the plotted table and explain every exclusion.

A citation points to another paper

Open the source and verify its bibliographic details.

Match the check to the error that would matter for your task.

32:00–34:00 (2 minutes). Ask for one example of a plausible-looking error the audience has encountered. The value of an agent's execution loop is that checks can be run and repeated; the researcher must choose meaningful checks. Another model agreeing is not the same as verifying against data or a source.
14 · Know where your data goes

Execution and model processing are separate

Where do tools run?

The working environment

Your computer, a remote machine or a hosted sandbox.

Where is input processed?

The model service

A hosted provider, or a local model if the system is configured for one.

Local execution can still send file excerpts and tool results to a hosted model.

Check the configured service, account terms and institutional rules before using restricted data.

Example data flow and account-dependent policies: Claude Code data usage

34:00–36:00 (2 minutes). Separate the interface, the execution environment and the inference service. Running a Python script locally does not establish that the surrounding agent session stays local. Training use, retention and external tool access are separate questions. Use synthetic or approved data for an initial trial.
15 · Control the scope

Use a bounded workspace

Sandbox

Technical limits on files, network access and other resources.

Approval policy

When does the work pause?

Rules that decide which actions need authorization.

  • Start with a project copy or branch and scoped access.
  • Keep raw data recoverable; inspect changes before sharing.
  • Review instructions from downloaded files, skills and websites.

Technical boundaries and approvals: Sandboxing · Agent approvals and security

36:00–38:00 (2 minutes). A branch or worktree helps recover code changes; it is not a security sandbox. A text request to preserve raw data is useful guidance, while filesystem permissions enforce an access boundary. Defaults vary. Explain prompt injection simply: a file or webpage can contain instructions that try to redirect the agent away from your task.

Reference · Copyable prompt

A reusable task brief

Goal: [the result I need]
Inputs: [files, definitions and relevant documentation]

First inspect the inputs and propose a short plan.
Use these rules: [sample, methods, software, output formats].
Keep these files unchanged: [raw inputs].
Save the results to: [output directory].

Run the work. Check: [counts, keys, units, known examples].
Report the changed files, commands run, checks performed,
assumptions and anything that remains unresolved.
Include instructions so I can reproduce the result.
Reference only. Replace each bracketed item with a concrete instruction. Verification requirements should reflect the errors that would matter for the specific task. Avoid asking the agent to choose an unspecified statistical test and immediately write a publication-ready interpretation.
